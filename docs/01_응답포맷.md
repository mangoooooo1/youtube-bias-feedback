# 응답 포맷 구현 명세서

## 프로젝트 컨텍스트

YouTube 시청 기록 기반 콘텐츠 소비 편향 피드백 시스템의 백엔드 서버다.
Node.js + Express + SQLite(better-sqlite3) 스택을 사용한다.
pnpm workspace 구조로 관리되며 서버는 `server/` 폴더에 위치한다.

### 현재 폴더 구조

```
server/
├── app.js
├── db.js
├── middleware/
│   └── responseHandler.js    ← 지금 만들 파일
├── routes/
│   ├── sessions.js
│   └── surveys.js
├── package.json
└── .env
```

### 기술 스택

- Node.js (CommonJS, require/module.exports)
- Express 4.x
- better-sqlite3
- dotenv

---

## 서비스 개요

Chrome 확장 프로그램이 클라이언트다.
확장 프로그램이 YouTube 시청 세션을 분석한 결과(원시 데이터 제외)를 서버로 전송하면
서버는 SQLite DB에 저장한다.

### 서버가 받는 요청 종류

| 엔드포인트      | 메서드 | 설명                |
| --------------- | ------ | ------------------- |
| `/health`       | GET    | 서버 상태 확인      |
| `/api/sessions` | POST   | 세션 분석 결과 저장 |
| `/api/surveys`  | POST   | 설문 응답 저장      |

---

## 구현할 파일: `server/middleware/responseHandler.js`

### 목적

모든 API 응답을 일관된 형식으로 반환한다.
라우터마다 `res.json()`을 직접 호출하지 않고 이 모듈의 함수를 사용한다.

## 성공 응답 포맷

### 구조

```json
{
  "success": true,
  "message": "string",
  "data": "object | null"
}
```

### 필드 설명

| 필드      | 타입           | 설명                       |
| --------- | -------------- | -------------------------- |
| `success` | boolean        | 항상 `true`                |
| `message` | string         | 성공 메시지. 기본값 `"ok"` |
| `data`    | object \| null | 응답 데이터. 없으면 `null` |

### 실제 응답 예시

```json
{
  "success": true,
  "message": "세션 저장 완료",
  "data": null
}
```

```json
{
  "success": true,
  "message": "ok",
  "data": {
    "status": "healthy",
    "timestamp": 1713600000000
  }
}
```

## 실패 응답 포맷

### 구조

```json
{
  "success": false,
  "message": "string",
  "code": "string",
  "detail": "string | null"
}
```

### 필드 설명

| 필드      | 타입           | 설명                                             |
| --------- | -------------- | ------------------------------------------------ |
| `success` | boolean        | 항상 `false`                                     |
| `message` | string         | 사용자에게 보여줄 에러 메시지                    |
| `code`    | string         | 에러 분류 코드 (아래 코드 목록 참고)             |
| `detail`  | string \| null | 개발 디버깅용 상세 메시지. 프로덕션에서는 `null` |

### 에러 코드 목록

| code                     | HTTP 상태 | 설명                  |
| ------------------------ | --------- | --------------------- |
| `MISSING_REQUIRED_FIELD` | 400       | 필수 필드 누락        |
| `INVALID_FIELD_VALUE`    | 400       | 필드 값 형식 오류     |
| `DUPLICATE_SESSION`      | 409       | 이미 존재하는 세션 ID |
| `NOT_FOUND`              | 404       | 리소스 없음           |
| `INTERNAL_SERVER_ERROR`  | 500       | 서버 내부 오류        |

### 실제 응답 예시

```json
{
  "success": false,
  "message": "필수 필드가 누락되었습니다.",
  "code": "MISSING_REQUIRED_FIELD",
  "detail": "anonymousId, sessionId, startTime, endTime 중 하나 이상이 없습니다."
}
```

```json
{
  "success": false,
  "message": "서버 오류가 발생했습니다.",
  "code": "INTERNAL_SERVER_ERROR",
  "detail": null
}
```

## 구현 요구사항

### 내보낼 함수 목록

```javascript
// 성공 응답
success(res, data, message);

// 실패 응답
fail(res, status, code, message, detail);

// Express 에러 핸들러 미들웨어 (app.js 맨 마지막에 등록)
errorHandler(err, req, res, next);
```

### 각 함수 상세 스펙

#### `success(res, data, message)`

| 파라미터  | 타입             | 기본값 | 설명              |
| --------- | ---------------- | ------ | ----------------- |
| `res`     | Express Response | 필수   | Express 응답 객체 |
| `data`    | object \| null   | `null` | 응답 데이터       |
| `message` | string           | `'ok'` | 성공 메시지       |

항상 HTTP 200을 반환한다.

#### `fail(res, status, code, message, detail)`

| 파라미터  | 타입             | 기본값                        | 설명                 |
| --------- | ---------------- | ----------------------------- | -------------------- |
| `res`     | Express Response | 필수                          | Express 응답 객체    |
| `status`  | number           | `500`                         | HTTP 상태 코드       |
| `code`    | string           | `'INTERNAL_SERVER_ERROR'`     | 에러 코드            |
| `message` | string           | `'서버 오류가 발생했습니다.'` | 에러 메시지          |
| `detail`  | string \| null   | `null`                        | 디버깅용 상세 메시지 |

#### `errorHandler(err, req, res, next)`

Express 전역 에러 핸들러다.
파라미터가 반드시 4개여야 Express가 에러 핸들러로 인식한다.

`err` 객체에서 다음 필드를 참조한다.

- `err.status` : HTTP 상태 코드. 없으면 500
- `err.code` : 에러 코드. 없으면 `'INTERNAL_SERVER_ERROR'`
- `err.message` : 에러 메시지

에러 로그는 반드시 `console.error`로 출력한다.
로그 형식: `[Error] METHOD /path : 에러 메시지`

### 에러 코드 상수

에러 코드 문자열을 하드코딩하지 않도록 상수 객체를 같은 파일 안에 정의하고 내보낸다.

```javascript
const ERROR_CODES = {
  MISSING_REQUIRED_FIELD: "MISSING_REQUIRED_FIELD",
  INVALID_FIELD_VALUE: "INVALID_FIELD_VALUE",
  DUPLICATE_SESSION: "DUPLICATE_SESSION",
  NOT_FOUND: "NOT_FOUND",
  INTERNAL_SERVER_ERROR: "INTERNAL_SERVER_ERROR",
};
```

## 라우터에서 사용하는 방법

구현 완료 후 라우터에서 아래처럼 사용한다.

```javascript
const { success, fail, ERROR_CODES } = require("../middleware/responseHandler");

// 성공
router.post("/", (req, res, next) => {
  try {
    const { anonymousId, sessionId, startTime, endTime } = req.body;

    // 필수 필드 검증
    if (!anonymousId || !sessionId || !startTime || !endTime) {
      return fail(
        res,
        400,
        ERROR_CODES.MISSING_REQUIRED_FIELD,
        "필수 필드가 누락되었습니다.",
        "anonymousId, sessionId, startTime, endTime 중 하나 이상이 없습니다.",
      );
    }

    // DB 저장 로직...

    return success(res, null, "세션 저장 완료");
  } catch (err) {
    next(err); // errorHandler로 전달
  }
});
```

## app.js 등록 방법

```javascript
const { errorHandler } = require("./middleware/responseHandler");

// 모든 라우터 등록 후 맨 마지막에 등록
app.use(errorHandler);
```

---

## 주의사항

- CommonJS(`require`/`module.exports`) 를 사용한다. `import`/`export` 사용 금지
- `detail` 필드는 개발 환경에서만 포함한다
  - `process.env.NODE_ENV === 'production'` 이면 `detail: null` 로 반환
- `errorHandler` 의 파라미터는 반드시 `(err, req, res, next)` 4개여야 한다
- 모든 라우터에서 try-catch의 catch 블록은 `next(err)` 로 errorHandler에 위임한다
- `success` 함수는 항상 HTTP 200만 반환한다. 201 같은 다른 상태 코드는 사용하지 않는다
